# Mac stage A (W0.3, W2.I2, W3.5, W4.3, W5.4, W6, W7): what was compared before the Mac copies were deleted

Nothing here was built or run (no Xcode, SwiftPM, cargo or Bazel). Every item is a `cmp`, `diff`, blob or `git ls-tree` comparison, or a pure-Python test. The core checkout used for the comparisons is iOS `shared/w1` 7fa7bc80 (fetched locally into `submodules/telegram-ios`).

## libprisma glue (CodeSyntax)

- Deleted: `submodules/CodeSyntax/CodeSyntax/CodeSyntax/Syntaxer.h` and `Syntaxer.mm`. The fork's `apple/Syntaxer.{h,mm}` is the merged iOS and macOS glue. Every Mac hunk is in it: `diff` of the old Mac files against the fork files shows only (a) `SyntaxerColor`/`SyntaxerFont` typedefs replacing `NSColor`/`NSFont` under `TARGET_OS_OSX`, (b) `static` on the file-local helpers, (c) the Mac initializer `initWithDark:...themeKeys:` kept as is, plus the iOS initializer and `-init`, (d) `colors == nil` falls back to the built-in palette (iOS). - The pbxproj group now points at `third-party/libprisma/libprisma/libprisma` (the fork's C++ core, same eight files) and `libprisma/apple`; header search paths gain `boost_regex/regex/include` and `libprisma/libprisma/libprisma`; `BOOST_REGEX_MAX_BLOCKS=1536` is defined (the cap the iOS BUILD and Android use). `Telegram.xcodeproj` bundles `libprisma/libprisma/libprisma/grammars.dat`.
- `tools/dev/tests/test_libprisma_shared.py` compiles the pure C++ core with clang++ against the new paths and runs the iOS host test (`SyntaxHighlighterRecursionTests.cpp`): ALL PASS.

## W7: Mac packages compile the iOS sources (symlinks, no copies)

SwiftPM does not allow a target path outside its package, so each Mac package keeps its `Package.swift` and reaches the iOS tree through tracked symlinks into `submodules/telegram-ios` (the same device the iOS lane used for OpusBinding, `SwiftPMLinks/`). `tools/dev/tests/test_shared_sources.py` checks that each one is tracked as a symlink and resolves to the intended core path. What was compared before each copy was deleted (`diff` of the Mac file against the iOS file at 7fa7bc80):

- **RingBuffer, EDSunriseSet**: `.h` identical; `.m` differs in the import of its own header only (`"RingBuffer.h"` vs `<RingBuffer/RingBuffer.h>`; `"EDSunriseSet.h"` vs `<Sunrise/EDSunriseSet.h>`). The iOS directory layout (`PublicHeaders/<Module>/`, `Sources/`, a `BUILD` file that is excluded) is used as is: `path: "CoreSources"`, `sources: ["Sources"]`, `publicHeadersPath: "PublicHeaders"`.
- **HLSPlayback**: the Mac files equal the iOS files except where iOS has more: the only Mac-side lines that disappear are two comment lines that moved. iOS adds `HLSForwardBuffer.swift`, `setMaxBufferAhead`, the size/duration clamps and the range-fit check (the Mac hardening was already in iOS), and one more test file (`HLSForwardBufferTests.swift`) plus one more test in `HLSPlaybackControllerPipelineTests.swift`. `Sources` and `Tests` are now symlinks to `submodules/HLSPlayback/{Sources,Tests}`; the README's copy instructions are replaced.
- **VP9Hardware**: `VP9HardwareDecoder.swift` and `WebMStickerDemuxer.swift` `cmp`-identical; the two Mac test files are subsets of the iOS tests (iOS adds the SwiftPM `Bundle.module` fixture lookup and the stats-delta asserts); the two `.webm` fixtures are `cmp`-identical and stay as real files, because `resources: [.copy("Resources")]` would copy a symlink, not the file. `VP9HardwareStickerReader.swift` and its test stay Mac-only.
- **SwiftMath**: the Mac `MathBundle` and `MathRender` trees differ from iOS in 14 files, and the only Mac-only lines are `Bundle.module` where iOS has `swiftMathFontsBundle()` (which is `Bundle.module` under `SWIFT_PACKAGE`); everything else is added in iOS (the iOS lane ported the Mac hardening). Both directories are symlinks. `latinmodern-math.otf/.plist` stay real files in the package (`.copy` of a symlink), `cmp`-identical to `submodules/TelegramUI/Resources/Fonts`.
- **Stripe**: seven files are symlinks (`STPCardValidator.{h,m}`, `STPBINRange.{h,m}`, `STPCardBrand.h`, `NSString+Stripe_CardBrands.{h,m}`). The Mac copies were older: no `cardBrand:` parameter on the expiry validator, no `STPCardBrandOther`, a shorter BIN table; `NSString+Stripe_CardBrands` and `STPCardBrand.h` were byte-identical or iOS-superset. The Mac callers and switches are adapted to the iOS API with the same hunks iOS has: `STPCardParams.m` and `STPPaymentCardTextFieldViewModel.m` pass `cardBrand:[STPCardValidator brandForNumber:...]`, `STPCard.m` maps `"other"` and prints `Other`, `STPImageLibrary.m` shows the unknown-card image for `STPCardBrandOther` (iOS uses `stp_card_placeholder_template`, which the Mac does not have). The UIKit/AppKit files stay per app.
- **QrStudioUI**: eleven logic files are symlinks into iOS's `QrStudioLogic` source set (compiled into this module, not a Swift module): `CodePaths`, `CodePillLogic`, `Color`, `ExportLayout`, `ExportMotion`, `ExportRenderer`, `Lens`, `LookSettings`, `Motion`, `ServerLook`, `SheetMotion`. Seven are identical or differ by iOS additions only; `CodePaths` (iOS adds `eyeParts` and a `canImport(QrCode)`), `ExportRenderer` (iOS: `UIKit`/`AppKit` aliases, the `Plane` struct moved, `qrStudioExportImage` returns `CGImage` on macOS as before), `Lens` (`isPersistent` default) and `SheetMotion` (a `height` channel with default 0, `frame(... height: = 0)`) are supersets the Mac lines map into. `QrStudioCodeMatrix.swift` equals iOS `QrCodeMatrix.swift` minus `public` (checked with `diff` after removing `public `), now a symlink to it. `QrStudioLook`, the views and the sticker decoders stay per app.
- **SceneEffects**: `DiamondAnimation`, `DiamondGeometry`, `GramDiamond.metal`, `LiquidGlassShapes.metal`, `LiquidGlassSurfaceReleasePolicy` are identical to the iOS files after stripping comments (Python comment-stripping diff) and are symlinks. NOT shared: `LiquidGlassShapesTypes.swift` differs only in the type name (`LiquidGlassShapesAppearance` vs iOS `LiquidGlassAppearance`), and the Mac already has a different `public enum LiquidGlassAppearance` in TGUIKit, so taking the iOS name here would make every file that imports both modules ambiguous. The iOS lane's note says to rename the Mac call sites; that needs the iOS name to change or a Mac module split, so it is deferred.
- **Svg**: not merged (iOS decision: needs a Mac build and a pixel comparison); `packages/Svg` stays.
