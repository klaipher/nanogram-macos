Before: a ringing call was an ordinary window (no Space, full-screen or hidden-app handling, no notification, no Dock attention); a ringing or busy call window closed with the red button left the session in `crossCallSession`, after which every later call was dropped as `.missed` with no log; the ring waited for `stateManager.isUpdating`.
  - Card: `PrivateCallScreen/IncomingCallCard` is a non-activating `NSPanel` (`.canJoinAllSpaces, .fullScreenAuxiliary, .ignoresCycle`, level `.statusBar`, top right of the main screen) with Decline and Accept, shown by `PeerCallScreen` while the state is `.ringing` and not removable. `PeerCallScreen.presentIncoming()` also `NSApp.unhide` and deminiaturizes the call window and shows it without the animated transition (`IncomingCallPolicy.shouldAnimateWindow`); `CallWindowTransition.present` has a failsafe at `maximumDuration + 0.6 s` so the window is ordered front even if the animation callback never fires.
  - Notification and Dock: `Telegram-Mac/account/IncomingCallPresenter` (new, one entry per ringing session) posts a UNUserNotification with the `incomingCall` category (Accept foreground, Decline), `.timeSensitive` interruption level and relevance 1.0 (no entitlement key added; the banner and Dock bounce need none), calls `NSApp.requestUserAttention(.criticalRequest)` while the app is inactive, and removes the notification and cancels the bounce when the session leaves `.ringing`, becomes removable or ends. Notification actions go through `UNUserNotificationsNew.didReceive` to `IncomingCallPresenter.respond` (accept, decline via `setToRemovableState` and `hangUpCurrentCall`, open). The caller name is replaced by the app name when the app is passcode- or screen-locked (`IncomingCallPolicy.hidesCaller`), in the notification and on the card.
  - Lifecycle: the call window has a close interceptor (`peerCallCloseAction`): ringing is declined, a recall termination (busy, disconnected) removes the session, any other state closes the window as before (active calls: hide only). `PCallSession.hangUpCurrentCall` and `setToRemovableState` stop the ringtone while ringing. `SharedAccountContext.dropCrossCall(ownedBy:)` clears `crossCallSession` only when it is the same session (the session now calls it; the argument-less version stays for the conference upgrade). `SharedWakeupManager` decides per ring with `IncomingCallRingLedger`: new session, replace an ended session (`PCallSession.isEnded`) instead of dropping the new call, answer `.busy` (was `.missed`) when a live call is active, ignore a repeated id; each decision is logged.
  - Ring path: the `isUpdating` gate became a 1.5 s grace (`IncomingCallPolicy.ringGateGrace`) and `getPrivateCallSessionData` has a 2 s timeout with `InitialData.fallback`. `PCallLaunch.swift` no longer has `fatalError("wtf")` (logs and continues). `CallDiagnostics.log` lines: ring state received, session created, window ordered front (visible, Space, app active/hidden, miniaturized), notification posted or failed, presentation ended, notification action.
  - Only the first ringing call per account is handled (as before); a second simultaneous ring is not answered busy. No avatar on the card (app icon instead).
  - Tests: NanogramRuntimeTests `IncomingCallPolicyTests`, `IncomingCallNotificationTests`; PrivateCallScreenTests `PeerCallWindowPolicyTests`. Built and tested in this release; not yet run on a device.
