## Unreleased

- **Lint fixes in the upstream picks**: the force unwraps the pre-push lint blocked in #239 (`QuickSwitcherModalController`: `modal` is unwrapped once before the digit handlers) and #235 (`SelectivePrivacySettingsController`: `callSettings.map`) are gone; no behaviour change.

- **Database key vault removed** (owner decision, 2026-11-05): the database key is again the `.tempkeyEncrypted` file beside the database, protected only by the default key or the passcode, exactly as upstream. The vault bound the key to the device keychain, so a Migration Assistant move or a backup restored to a new device could not open the database. No Mac ever ran a vault build (Direct builds have no provisioning profile, the keychain probe failed and the legacy path ran), so no migration back exists. Removed: `NanogramKeyVault` (source, header, tests), the vault adoption, rewrap and keychain probe in `submodules/BuildConfig` (`BuildConfig.m`/`.h` are back to the state before 3366e52d; `change`/`remove` return nothing again), the `enableKeychainWrapping` calls in `AppDelegate` and `ShareViewController`, and the "can't access its key in the Keychain" Retry / Quit alert with `unlockAndLaunch` (9f4711be; the launch code is inline again). The `BuildConfigTests` target stays with new tests of the plain behaviour. Two small data-safety deviations from upstream: the old plain `.tempkey` is only removed after its encrypted copy was written, and re-encrypting with no readable key does nothing instead of deleting the key file. No entitlement change: the vault commits never touched entitlements. A `.tempkeyVault` file, if one ever existed, is ignored and never touched. The `Key vault` bullet of the night review fixes below no longer applies.
